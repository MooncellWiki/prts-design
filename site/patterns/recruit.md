# 公招计算

工具页的样例：现网[公招计算](https://prts.wiki/w/%E5%85%AC%E6%8B%9B%E8%AE%A1%E7%AE%97)（= prts-widgets 的 `HrCalculator` Widget）的重新设计。和[干员一览](/patterns/operators)不同，这页不只换视觉——**算法的口径也照游戏改了**：现网把选中标签的所有子集各列一行，这里按游戏的招募流程来（招募位上 5 个标签 → 至多选 3 个 → 定招募时限），回答的是「这 5 个里选哪几个」。干员数据、词缀、地址栏 `?filter=` 的写法与现网一致，现网的分享链接在这里照样能用。

源文件 `preview/_src/pages/recruit.html`，`python3 scripts/build-preview.py` 生成；单文件离线版在 `dist/recruit.html`。数据是现网 Widget 运行时那条 cargoquery 的快照 `preview/vendor/recruit/data.js`（160 位可公开招募的干员，`node scripts/fetch-recruit.ts` 重抓）；头像不入库，运行时从 `media.prts.wiki` 取，取不到时留深色底框。

## 对着游戏

规则与样式都查了游戏本体（2.7.71 客户端 + `gacha_table`），页面上凡是写「游戏里」的都有出处：

| 游戏 | 出处 | 页面上 |
|---|---|---|
| 至多选 3 个标签 | `RecruitBuildConfigStateBean.MAX_TAG_SELECT_NUM = 3`；界面标题「职业需求（最多3项）」 | 组合只算 1–3 项 |
| 一个招募位 5 个标签 | 服务器下发（`SlotModel.tags`），客户端没有这个常数 | 面板封顶 5 个 |
| 时限 1:00–9:00、10 分钟一档，默认 1:00 | `MIN_BUILD_TIME` / `MAX_BUILD_TIME` / `MINUTE_MILLSEC_UNIT`；`recruitConstants.maxRecruitTime = 540` | 时限三档，默认最长一档 |
| 时限 → 稀有度范围 | `recruitRarityTable`：≤ 3:50 出 1–4★，4:00–7:30 出 2–5★，7:40–9:00 出 3–5★ | 三档的范围 |
| 稀有标签 → 星级 | `specialTagRarityTable`：高级资深干员 → 6★，资深干员 → 5★ | 6★ 只在组合含【高级资深干员】时算 |
| 9:00 才锁定稀有标签 | 招募说明 `recruitDetail`；开始招募的确认框「当前招募时限小于9小时，未锁定稀有职业需求」 | 时限提示；非最长一档时含稀有标签的组合记「不保底」 |
| 「可获得的干员」稀有度块 | `BuildConfigRarityViewModel.InitData`：范围内蓝块，选中稀有标签的那一星变黄、上限抬到那一星 | 时限栏右侧的稀有度块，同一算法 |
| 标签钮四种皮 | 预制件 `recruit_page` 的 `btn_tag_item`：`btn_request` `#313131` 白字 / `btn_request_choose` `#0098DC` / `btn_request_r` 深灰 + 黄色半调网点、黄字 `#FFEB04` / `btn_request_r_on` `#FFD800` 黑字 | 已选格子与组合标签 `.hr-tagbtn`；稀有标签芯片选中是黄底黑字 |
| 可公招干员、不可寻访（绿字）的干员 | `recruitDetail` 的名单 | 与现网快照逐一核对：160 位、标签、18 位「限」全部一致 |

游戏客户端里**没有**的：标签组合 → 干员的计算（抽取在服务器），所以也没有「保底」的界面可以照；这部分是页面自己的设计。

## 现网的问题

- **选多少个都行**。四行筛选（资历 / 职业 / 位置 / 词缀）各带「全选」，可以把 29 个标签全点上；游戏里一个招募位只出现 5 个。
- **组合不限个数**。结果把选中标签的每个子集各列一行——选 5 个标签就有 4 个、5 个标签的组合，游戏里最多只能选 3 个，这些行选不出来。
- **看不出保底**。行按「平均星级」排（1★ 按 3.5 计），一行保底几星要自己在头像底色里找最低的那个；1★ / 2★ 一直混在里面，而 9:00 的招募根本不出它们。
- **没有招募时限**。时限决定稀有度范围，两个稀有标签、支援机械该拉多久，页面上都没有。
- 头像只有底色区分稀有度、没有名字；分享链接是一张两行的 `wikitable`，整段 URL 摊在页面上。

## 标签面板

- **面板头 = 招募位上的 5 格**。选中的标签依次落进格子，空格是虚框带序号——一眼看得到还差几个；点格子取消。右边是 `n / 5` 与「清空」（下一个招募位从头选）。
- **最多 5 个**。选满后其余[筛选芯片](/components/chip)压淡（`aria-disabled`，仍可聚焦），再点给一句 [Toast](/components/toast)。友站 [arkntools](https://github.com/arkntools/arknights-toolbox) 的公招计算同样封顶 5 个（`MAX_TAG_NUM`）。现网链接里超过 5 个的照收，另出一条提示。
- **四行按社区通行的归类摆**：资质（高级资深干员 / 资深干员 / 新手 / 支援机械）· 位置 · 职业 · 词缀——游戏数据 `gachaTags` 自己不分组，友站也是这四类。现网把「支援机械」放在词缀里、「新手」放在资历里。
- **两个稀有标签另一套皮**，同游戏：芯片未选时金字金框，选中黄底黑字（普通标签选中是青底）；落进格子 / 出现在组合里是深灰底 + 黄色半调网点、黄字。
- **职业带图标**：同干员一览，游戏筛选面板的白线稿当 CSS 遮罩、颜色取 `currentColor`。
- **单选即可保底的标签带一枚小方块**（右上角，颜色 = 保底的稀有度）：不用点就知道哪些标签一出现就值得选。由数据算出，不是写死的。

## 招募时限

游戏里 1:00–9:00、每 10 分钟一档；稀有度范围只有三段（`recruitRarityTable`，现网[公开招募](https://prts.wiki/w/%E5%85%AC%E5%BC%80%E6%8B%9B%E5%8B%9F)页的表同），所以只给三档，每档写明范围：

| 时限 | 可能出现 |
|---|---|
| 1:00 – 3:50 | 1 – 4★ |
| 4:00 – 7:30 | 2 – 5★ |
| 7:40 – 9:00（默认） | 3 – 5★ |

时限栏右侧是游戏那排「可获得的干员」稀有度块：范围内的星级蓝底白字；选了稀有标签，它对应的那一星变黄、范围上限抬到那一星。

6★ 只在组合里有【高级资深干员】时算进来（同现网 Widget 的 `can5`）；组合含【资深干员】时 5★ 不受时限范围限制。但稀有标签只在 9:00 锁定——时限不在最长一档时，含稀有标签的组合落到「不保底」，行上写「未拉满 9:00，标签可能被划掉」。选了相关标签时出一条[消息](/components/message)，带一枚直接改时限的按钮：

- 【资深干员】/【高级资深干员】：最长一档时提示「拉满 9:00 才锁定，选上它必得 5★ / 6★」；其余两档是警告，用游戏确认框的原话「招募时限小于 9 小时，未锁定稀有职业需求」；
- 【支援机械】：想要 1★ 支援机械，时限不要超过 3:50。

## 结果

- **每组至多 3 个标签**；一组的干员 = 带齐这几个标签、星级落在当前时限范围里的。**保底 = 这组里最低的星级**。
- **按保底分层**：保底 6★ / 5★ / 4★ 各一层，层标题带稀有度色；整组都是 1★ 的单列一层「必得支援机械」；保底 3★ 及以下的收在最后一层「不保底」，前面有保底层时默认收起。层内标签少的在前、干员少的在前。
- **结论先说**：结果上面一句话——几组能保底 4★ 以上、最高几星、是哪一组、还能再选几个。
- **多加一个标签却圈不出更小范围的组合不列**（与它的子组合是同一批干员），列表短一截。
- 每组一行：左边是标签（游戏的深灰标签钮）+「几位 · 几星到几星」，右边是干员——头像 + 稀有度色条 + 名字，整块链到干员页；悬停 / 聚焦出[提示](/components/tooltip)（星级、全部标签）。只能通过公开招募获得的右上角一枚「限」（现网的绿色「限」字，判定同现网：获得方式里没有任何寻访）。
- 一组超过 28 位（单选【资深干员】= 全部 5★）先出 24 位，其余收在「+N」后面。
- 窄于 760 时标签挪到干员上面。

## 保底速查

一个标签都没选时，结果区不留白：列出**全部能保底 4★ 以上的最小组合**（9:00；不含资质那四个标签），按保底 5★ / 4★ 分层、排成多列的格子。「多加标签没把保底抬高」的不列。这就是现网「公开招募」页手工维护的那几张 TAG 组合表——这里由数据算出，新干员进公招后不用人改。友站的「查看保底词条组合」开关是同一件事。

## 地址栏

- `?filter=` 与现网一致：`@urlpack/json`（MessagePack → Base58）编码的 `{ profession, position, rarity, tag }` 四个位图，分组与组内次序照 Widget 的 `utils.ts`——页面上怎么归类（支援机械挪到资质）不影响编码。样例页自带一份几十行的编解码，与 `@urlpack/json` 逐字节对过。
- 时限是新加的，另用 `?t=0|1`（默认最长一档不写）。不能塞进 `filter`：现网 Widget 读到不认识的键会把它当位图写坏。
- 「复制分享链接」一枚幽灵按钮 + Toast，不再把整段 URL 摊在页面上。

## 没有照搬的

- **截图识别**（友站有：OCR 招募界面截图直接点上 5 个标签）没做——要引 OCR 引擎或第三方接口，是 Widget 的功能决定，不是版式问题。面板头那 5 格留着位置，将来「识别截图」按钮放在「清空」旁边。
- **`.hr-*` 没进设计系统**。筛选行与干员一览的 `.ol-row` 是同一个东西，等两边一起提成组件。
- **没有做无 JS 的兜底**（现网也没有）。
